> 分工 B/C 交付的运维手册。**VPS 侧已部署完成并验收通过**（2026-11-02 更新：LLM 出口代理已接入 DeepSeek）。

## 1. VPS 网关（分工2）——已部署 ✅

**现状快照**

| 项 | 值 |
| --- | --- |
| 服务器 | 阿里云 Debian 13（地址与登录方式见团队群，勿写入公开文档） |
| 代码位置 | `/opt/piagent/server`（venv: `.venv/`） |
| 服务 | systemd `piagent-server`（开机自启，崩溃自动拉起） |
| 监听 | `0.0.0.0:8000`（uvicorn） |
| 对外入口 | `http://<VPS地址>/piagent`（经 nginx 反代；8000 端口被安全组拦截，未另放行） |
| 前端 | 网关根路径即正式用户界面（`frontend/` 同步而来）；`/piagent/debug.html` 为联调控制台 |
| 数据 | `/opt/piagent/server/data/piagent.db`（SQLite：用户/设备/审计） |
| LLM 代理 | **已配置**（DeepSeek `deepseek-flash`，Key 在 `/opt/piagent/server.env`，权限 600） |

**常用运维命令**

```bash
systemctl status piagent-server          # 状态
journalctl -u piagent-server -f          # 日志
systemctl restart piagent-server         # 重启
cd /opt/piagent/server && .venv/bin/python manage.py add-user <名>      # 建用户并签发访问令牌（只显示一次）
cd /opt/piagent/server && .venv/bin/python manage.py token <名>        # 轮换访问令牌（旧令牌立即失效）
cd /opt/piagent/server && .venv/bin/python manage.py list-users
cd /opt/piagent/server && .venv/bin/python manage.py add-device <设备ID> --owner <名>
curl -s http://127.0.0.1:8000/api/health   # llm_proxy 应为 configured
```

**用户认证模型（2026-11 起）**：网页端**仅访问令牌登录**（`pat-xxx` 换 JWT），
注册与密码登录已在服务端关闭（403）。给队友开账号 = `add-user` 后把打印的令牌线下交付；
泄露/离职 = `token` 轮换，旧令牌立即失效。

**更新部署**（本机执行，rsync 排除数据目录与 venv）

```bash
rsync -az --delete --exclude .venv --exclude data --exclude __pycache__ --exclude test.env \
  server/ root@<VPS地址>:/opt/piagent/server/
ssh root@<VPS地址> 'systemctl restart piagent-server'
# 前端改动先 ./scripts/sync_frontend.sh 再 rsync（server/static 随 server/ 一起同步）
```

**接入真实 LLM**（已配置，复现参考）

```bash
vi /opt/piagent/server.env   # 三行，模板见 server/server.env.example：
# PIAGENT_LLM_BASE_URL=https://api.deepseek.com/v1   （以版本路径结尾）
# PIAGENT_LLM_API_KEY=sk-xxx
# PIAGENT_LLM_MODEL=deepseek-flash
systemctl restart piagent-server
# Agent 侧 config.toml 的 llm_mode = "proxy"（树莓派出厂配置即 proxy）
```

**nginx 说明**：80 端口与本服务器上其他项目（packhub）共用，PiAgent 挂在 `location ^~ /piagent/`（含 WebSocket 升级头），配置见 `/etc/nginx/sites-enabled/packhub`（改动前有备份 `/etc/nginx/packhub.bak`）。

**从零复现部署**：上传 `server/` → `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt` → `cp piagent-server.service /etc/systemd/system/` → 建用户/设备 → 启动。nginx 部分：`/etc/nginx/conf.d/piagent-map.conf`（Connection upgrade map）+ packhub 站点内的 `/piagent/` location。

## 2. 树莓派 Agent（分工3 + 分工4 真机）

```bash
# ① 依赖（Pi OS bookworm 自带 Python 3.11+）
sudo apt install -y python3-venv git
git clone <本仓库> /opt/piagent && cd /opt/piagent/agent
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# ①b 真机舵机版依赖（仅跑 device_mcp_server.py 需要）
.venv/bin/pip install -r ../devices/requirements-device.txt   # gpiozero + rpi-lgpio

# ② 配置（token 从 VPS manage.py add-device 获取）
cp config.example.toml config.toml && vi config.toml
#    server_url = "ws://<VPS地址>/piagent"
#    device_id / device_token 填写；llm_mode = "proxy"（Key 在 VPS 端）
#    [[mcp.servers]]：
#      联调（无硬件）   → args = ["../devices/mock_mcp_server.py"]
#      真机（SG90 舵机）→ args = ["../devices/device_mcp_server.py"]
#                         env = { PIAGENT_SERVO_PIN = "17" }   # 默认 GPIO17，可改

# ③ 手动验证
.venv/bin/python -m pi_agent        # 看到"注册成功"即打通

# ④ systemd 守护
sudo cp piagent-agent.service /etc/systemd/system/
sudo systemctl enable --now piagent-agent
journalctl -u piagent-agent -f
```

**SG90 舵机接线**：信号线（橙/黄）→ GPIO17（`PIAGENT_SERVO_PIN` 可改）· VCC（红）→ 5V
（演示轻载可取自 Pi，带负载请外部 5V 供电）· GND（棕）→ GND（外部供电必须共地）。
非树莓派环境或未启用 GPIO 时 `device_mcp_server.py` 自动降级模拟（返回 `mode:"simulated"`），
不影响 `e2e_test.py` 验收。工具契约详见 `docs/接口文档/mcp_tools_schema.md`。

无树莓派时的联调方式：任何能出网的机器装好 agent 依赖、配置后运行即可（当前演示即此形态，
设备 `pi-dorm-01` 跑在开发机上，`pi-live-01` 为树莓派实机预留）。

## 3. 安全基线

- **用户认证仅访问令牌**（2026-11-02 起）：注册/密码登录关闭（403），令牌由 `manage.py` 签发与轮换，
  服务端只存 sha256，登录失败带固定延时防枚举——开放注册+弱共享密码等于人人可操控设备；
- 设备 token、JWT 密钥、LLM Key 均不入库（`agent/config.toml`、`server/data/`、`server.env` 都已 gitignore）；
- **SSH 已切换密钥登录**（2026-11-02）：`PasswordAuthentication no` + `PermitRootLogin prohibit-password`，
  仅公钥可登录 root；变更前已验证密钥通路、挂过 5 分钟自动回滚保险。root 密码仅剩阿里云
  VNC 控制台登录用途，忘记密钥时用控制台救援。部署机 `~/.ssh/id_ed25519` 即授权密钥；
- **建议**：生产前端上线后收紧网关 CORS；有域名后给 nginx 配 TLS（ws:// → wss://，Agent 的 server_url 相应改 wss://）。
