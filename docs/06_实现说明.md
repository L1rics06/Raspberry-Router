# 实现说明：从只做部署扩展到整个分工4

## 1. Pi5真实PWM驱动

1. 当前问题：旧包只有模拟夹具，无法上机驱动真实舵机
2. 修改位置：task4/pwm_driver.py、scripts/enable_pi5_pwm.sh、prepare_pi5_pwm.sh
3. 修改方案：修改前没有真实后端；修改后使用Linux PWM sysfs和Pi5 RP1 PWM0，固定BCM12/物理32脚，周期20000000ns，1500us写成1500000ns
4. 整体思路：先启用overlay和权限，运行时只读识别模型、引脚复用、控制器地址，再取得全机文件锁，第一条动作才使能PWM
5. 修改理由：使用Pi5实际外设，避免依赖旧pigpio/RPi.GPIO示例，也不把可变化的pwmchip编号写死
6. 好处与作用：波形由硬件生成，Python只改变脉宽；启动不自动输出位置，能直接连接舵机信号线做空载验证
7. 注意事项与验证：文件系统夹具验证纳秒换算和停止标记，控制器识别排除风扇；ARM系统、真实频率、电平和供电仍待上机测量

## 2. 按压算法与标定

1. 当前问题：SG90各批次行程不同，机构位置也无法远程猜测，旧型号标定不能复用
2. 修改位置：task4/servo_control.py、servo_cli.py、configs/
3. 修改方案：修改前等待别人交三个位置；修改后提供窄范围小步调试和交互式home/on/off记录，默认不允许未标定墙灯动作
4. 整体思路：每次回home、压目标端、回home、停止PWM；脉宽限幅，每帧最多改变step_us，保持JSON状态供debug
5. 修改理由：按压目标和实际几何相关，必须现场标定；位置命令不能冒充角度回读或灯光反馈
6. 好处与作用：可独立完成标定，工具自动同步驱动配置和验收记录；故障锁定、不自动重试
7. 注意事项与验证：单元测试包含启动无动作、限幅、渐变、退回、失败锁定、假布尔、仿真参数拒上真机；首次1500us必须脱离开关

## 3. MCP工具与兼容入口

1. 当前问题：上游当前只有5个通用工具，没有寝室墙灯控制
2. 修改位置：devices/wall_light_mcp.py、all_devices_mcp.py
3. 修改方案：修改前无light.set；修改后提供light.set和devices.status，可选合并原5个工具，共6个
4. 整体思路：MCP只接收布尔开/关，底层读取标定；stdout只走协议，错误写stderr和JSON
5. 修改理由：给上层固定接口，避免暴露任意舵机角度；合并入口解决devices.status重名
6. 好处与作用：原有LED、风扇、继电器和传感器契约可以继续使用，单舵机不强制安装其他外设依赖
7. 注意事项与验证：正式控制算法的sim后端通过MCP动作检查，合并入口通过原有32项契约；真实GPIO不可用时直接失败，不暗中模拟

## 4. Agent错误传播

1. 当前问题：原Agent对设备ok=false仍返回外层ok=true，聊天还可能继续宣称成功
2. 修改位置：runtime_source/agent/pi_agent/mcp_client.py、agent_loop.py
3. 修改方案：修改前仅拼接返回文本；修改后检查MCP isError、JSON结构和严格布尔ok，用MCPCallError保留失败payload
4. 整体思路：直控失败内外层均false，聊天在错误处立即返回，不再把错误交给模型二次包装；工具重名直接报错
5. 修改理由：设备失败必须在UI和自动验收中可见，不能因模型的表述变成成功
6. 好处与作用：减少误判与重复按压，提供可供分工3合并的补丁，同时保留原始上游快照
7. 注意事项与验证：异步测试验证协议错误、设备错误、非法参数不调用、故障后不继续请求模型；当前完整本地链路50项通过

## 5. 部署和停止

1. 当前问题：新驱动需要overlay、权限、唯一控制者及退出后的PWM清理
2. 修改位置：scripts/enable_pi5_pwm.sh、prepare_pi5_pwm.sh、stop_pi5_pwm.sh、task4/deploy.py
3. 修改方案：修改前仅Agent service；修改后增加只准备不使能的开机服务、控制锁与停止标记，Agent依赖准备服务并在退出后补充清理
4. 整体思路：root仅准备sysfs权限，实际控制用正常账号；配置通过PIAGENT_CONFIG传入，停止时处理MCP进程与PWM
5. 修改理由：硬件PWM可能在进程异常终止后继续输出，需要独立清理路径，停止标记阻止旧进程重新使能
6. 好处与作用：能按命令部署、自启、停止和恢复，减少双进程争用和错误配置
7. 注意事项与验证：2个PowerShell和7个Bash脚本已做语法检查；systemd、权限和退出时真实引脚电平仍需在Pi实测，物理断电始终是卡住时的直接处理

## 6. 文档、机构与证据

1. 当前问题：此前只交部署工具，缺接线、安装方向和可照做的上机流程
2. 修改位置：README、docs/、mechanics/、reference/、reports/
3. 修改方案：修改前等待本组其他人补实现；修改后给固定脚位、供电方案、双臂布局、校准工具和完整测试顺序
4. 整体思路：先脱离开关空载，再装机构小步标定，最后本地、MCP、网关逐级验证并录制视频
5. 修改理由：现场尺寸、电源能力和位置无法用仿真代替，需要明确每一步该看什么
6. 好处与作用：拿到Pi即可按步骤尝试，无需继续等待驱动开发；其他项目分工只需按接口和凭证对接
7. 注意事项与验证：不预填实测值、不自动确认灯光亮灭；报告区分sim、GPIO软件通过和操作员证据完整性
