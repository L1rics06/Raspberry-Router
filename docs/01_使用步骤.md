# 上机测试：按顺序做

## 1. 准备和接线

使用你最新确认的SG90微型9g位置型PWM舵机，供电改为5V；不能使用360度连续旋转型代替位置型

准备Pi5及其足额USB-C电源、SG90和三根连接线；本版先直接从Pi的5V排针取电，不使用原6V电源或电池

单只SG90可先这样做空载测试；带开关负载时仍需确认Pi供电余量、无欠压和重启，不能凭“微型9g”直接认定稳定

**断电时接线**：

| 从哪里 | 接到哪里 |
|---|---|
| 舵机橙/白信号线 | Pi5 BCM12＝物理32脚 |
| 舵机红色线 | Pi5物理2脚5V |
| 舵机棕/黑色线 | Pi5物理6脚GND |
| Pi5 USB-C | Pi5电源 |

红线接5V电源脚，棕/黑线接GND，橙色信号线接GPIO12；不能把红线接3.3V或GPIO12

用三根转接线分别连接，不能把SG90的一体三针插头直接套到Pi上任意相邻的三个针脚

Pi排针局部编号如下，只根据编号定位，不凭照片上下方向猜测：

```text
物理奇数列        物理偶数列
 1  3V3            2  5V   ← SG90红色电源线
 3  GPIO2          4  5V
 5  GPIO3          6  GND  ← 共地线
      ……
29  GPIO5         30  GND
31  GPIO6         32  GPIO12 ← 舵机橙/白信号线
33  GPIO13        34  GND
35  GPIO19        36  GPIO16
37  GPIO26        38  GPIO20
39  GND           40  GPIO21
```

PWM高电平仍是3.3V；首次空载确认SG90能识别，若供电与波形正常却不响应，核对实物是否位置型和信号要求，不能把5V电源接入GPIO信号脚

如果带开关时Pi欠压/重启，备用方案为SG90红线接独立5V正极、棕/黑线接独立负极，并把该负极与Pi物理6脚共地；此时红线从Pi物理2脚拔除，不并联两个电源正极

## 2. 将整个包放到Pi

解压交付ZIP，进入包含README.md的目录；不要复制Windows的.venv目录

首次可安装系统依赖：

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip raspi-utils
bash scripts/setup_pi.sh
bash scripts/servo.sh init
sudo bash scripts/enable_pi5_pwm.sh "$(id -un)"
```

脚本备份config.txt，添加 `dtoverlay=pwm,pin=12,func=4`，建立PWM准备服务与gpio权限；不会自动产生舵机脉冲，也不升级固件

断电时先完成三线连接；若接线仍需调整，先关闭Pi并拔掉USB-C电源，改线后再通电。启用PWM后按提示重启Pi：

```bash
sudo reboot
```

重新登录后回到交付目录：

```bash
bash scripts/servo.sh doctor
```

应看到ok=true、BCM12、物理32脚、50Hz和PWM控制器地址；pwmchip编号可能变化，不用手改编号

若doctor不通过，查看 [故障排查](07_故障排查.md)，不要先运行运动命令

## 3. 第一次只做空载中位测试

先拆掉舵盘或让摆臂完全离开开关，清理旋转范围，再给Pi和SG90通电；不要边通电边在排针上移动裸线

```bash
bash scripts/servo.sh pulse --us 1500 --hold 0.5 --actuate
bash scripts/servo.sh pulse --us 1490 --hold 0.5 --actuate
bash scripts/servo.sh pulse --us 1510 --hold 0.5 --actuate
```

应看到SG90先到1500us初始中位，再在附近小幅动作；每条命令输出有限时长后停PWM。SG90各批次行程不同，不把1500us或两个端点换算成固定角度

默认只允许1400～1600us小窗口，本包保护范围为1000～2000us，不进行旧型号500～2500us扫动。SG90顶住、持续异响或Pi重启时先停止PWM并及时切断供电，断电后查供电/机构

另开终端可停止并锁定PWM：

```bash
bash scripts/servo.sh stop
```

停止PWM不等于切断5V，不保证每款SG90都完全卸力。恢复前先停止MCP/Agent或本地控制程序、确认机构安全，然后：

```bash
bash scripts/servo.sh reset-stop
```

## 4. 安装机构

按 [安装与调校](../mechanics/安装与调校.md) 进行：舵机轴与墙面平行且水平，双臂舵盘在中位时竖直；一个方向用上臂压上端，另一个方向用下臂压下端

中位必须离开开关，两端均有间隙；只在开关面板外侧固定，不拆市电接线部分。先移开接触点验证方向，再靠近开关小步调试

## 5. 交互标定，程序记录三个真实位置

```bash
bash scripts/servo.sh calibrate --operator "实际操作人姓名" --actuate
```

按提示确认后：

1. 在摆臂离开开关的位置输入 `home`
2. 用 `+` / `-` 每次改变10us，或输入具体微秒值，小步靠近能开灯的端部
3. 实际观察灯已打开后输入 `on`，程序记录该位置并退回已记录的home
4. 继续小步测试另一方向，实际观察灯关闭后输入 `off`，程序再次退回home
5. 输入 `save`，确认退回有间隙、手动仍可操作，并确认这是上下两端分别开/关的普通单控翘板开关

窗口不够时可输入 `range 1300 1700`，只修改范围，明确确认后仍按小步动作；始终限制1000～2000us，并拒绝过大/过慢的动作配置

输入q可退出不保存。save保存 `configs/servo.local.toml` 并同步 `handoff/calibration.local.toml`，不用手工复制位置值

双控线路无法仅凭固定上/下端位置保证灯亮灭，此时不要确认单控，应更改机构目标或增加灯光反馈后再用

## 6. 本地真实开关测试

无需网关、模型或其他分工即可运行：

```bash
bash scripts/servo.sh on --actuate
bash scripts/servo.sh off --actuate
bash scripts/servo.sh cycle --cycles 1 --actuate
```

观察实际流程：回home → 压目标端 → 回home → 停PWM；确认能手动操作开关，无顶压、打滑、持续异响和Pi重启

一轮稳定后再运行10轮，每轮开和关各一次：

```bash
bash scripts/servo.sh cycle --cycles 10 --actuate
```

此阶段应实际观察并录像。程序只知道发送了哪些脉宽，不知道灯是否真实亮灭，因此lamp_state仍为unknown

SG90扭矩远小于之前的20kg舵机，如果压不动开关，先调整摆臂长度和安装间隙；仍压不动就需要改机构或选更合适舵机，不能让SG90持续堵转

## 7. 记录电气实测并检查MCP

完成真实接线、空载和负载供电测试后再填写，不能代填没测过的项目：

```bash
bash scripts/servo.sh record-electrical --operator "实际操作人姓名"
bash scripts/run.sh preflight --profile profiles/hardware.local.toml
bash scripts/run.sh mcp-check --profile profiles/hardware.local.toml
bash scripts/run.sh mcp-check --profile profiles/hardware.local.toml --actuate --cycles 1
```

预检核对真实Pi5、PWM准备、供电记录、标定文件及驱动实际配置是否一致；纯本地MCP检查不需要团队网关令牌

如果已有Agent/MCP在运行，先停止它再做本地调试，同一舵机不能由两个进程控制

## 8. 接团队网关并自启动

向项目网关管理员领取：网关URL、设备ID、该设备dev令牌、你账号的pat令牌

编辑 `profiles/hardware.local.toml`：填gateway.base_url，agent_device_id与gateway.device_id填同一个真实ID。舵机入口和标定路径已经预置，不用再等人写驱动

```bash
read -rsp '设备令牌: ' TASK4_DEVICE_TOKEN; echo
export TASK4_DEVICE_TOKEN
bash scripts/run.sh prepare-agent --profile profiles/hardware.local.toml --user "$(id -un)"
unset TASK4_DEVICE_TOKEN
bash scripts/service.sh install
bash scripts/service.sh start
bash scripts/service.sh status
```

生成的服务在独立包使用runtime_source/agent修复版，在仓库集成版使用已修复的根目录agent。已有Agent实例应先由负责人安排迁移，不能两个实例用同一设备ID连接

经网关验收：

```bash
read -rsp '访问令牌: ' TASK4_ACCESS_TOKEN; echo
export TASK4_ACCESS_TOKEN
bash scripts/run.sh gateway-check --profile profiles/hardware.local.toml
bash scripts/run.sh gateway-check --profile profiles/hardware.local.toml --actuate --cycles 10 --chat --report reports/hardware-gateway.json
unset TASK4_ACCESS_TOKEN
```

最后一条为20次直控按压加2次聊天按压，共至少22次。真实聊天调用团队模型，可能产生其正常费用；本包Windows demo不产生模型费用

也可以使用原项目路径的新版E2E，默认只读，动作需显式允许，访问令牌仍从TASK4_ACCESS_TOKEN读取：

```bash
.venv/bin/python scripts/e2e_test.py --profile profiles/hardware.local.toml
.venv/bin/python scripts/e2e_test.py --profile profiles/hardware.local.toml --actuate --cycles 10 --chat --report reports/hardware-gateway.json
```

## 9. 提交现场记录

将 `handoff/physical-evidence.example.json` 复制为 `handoff/physical-evidence.local.json`，填写实际观察；录像放到包内evidence目录，附件路径相对该JSON，例如 `../evidence/开关验收.mp4`

```bash
bash scripts/run.sh evidence --technical-report reports/hardware-gateway.json --evidence handoff/physical-evidence.local.json --report reports/physical-evidence.json
```

operator_evidence_complete=true只表示记录和附件完整，最终仍需现场人员查看视频并确认实物效果
