# MCP接口和完成标准

## 数据流

```mermaid
flowchart LR
    A[网页直控或聊天] --> B[VPS网关]
    B --> C[树莓派Agent]
    C --> D[light.set]
    D --> E[限幅与串行动作]
    E --> F[RP1硬件PWM]
    F --> G[BCM12物理32脚]
    G --> H[舵机按压后退回]
```

## light.set

参数为一个必填布尔值on，拒绝字符串或数字：

```json
{"on": true}
```

true按压现场标定的开灯端，false按压关灯端；不使用toggle，因此同一目标不会凭软件猜测当前灯状态

正常返回JSON文本，例如：

```json
{"ok":true,"mode":"gpio","requested_on":true,"lamp_state":"unknown","trace":["home","press_on","home"],"last_command_us":1500}
```

last_command_us为最后发送的脉宽，不是位置传感器回读；示例1500不是强制机构home值

未标定、非单控开关、参数错误、越界、PWM失败、停止锁定都返回ok=false。发生真实驱动故障后锁住后续动作，需要检查后重启控制器，不自动重试

流程预算限制在4.5秒内，为上游“不长阻塞超过5秒”的工具契约留出余量；Python不是实时系统，实际耗时仍需现场观察

## devices.status

无参数，只读，不发送PWM

```json
{"ok":true,"mode":"gpio","ready":true,"calibrated":true,"lamp_state":"unknown","gpio_bcm":12,"physical_pin":32,"channel":0,"frequency_hz":50,"errors":{}}
```

仿真明确返回mode=sim和fixture=true，真实驱动不在硬件不可用时降级仿真

合并入口保留led/fan/relay/pins字段和原有顶层errors，other_devices保留完整原始快照；舵机ready只表示舵机控制准备情况，other_devices_ready单独说明原设备状态

## 原设备兼容

`devices/all_devices_mcp.py`合并后保留原来的led.set、fan.set、relay.set、dht.read、devices.status，并增加light.set，共6个工具

该合并入口已通过原仓库32项仿真契约自检，不改原5个工具的参数规范；实际外设接线仍需现场验证

前次发现的顶层errors遗漏已修复：原设备错误保持原键，舵机错误重名时加servo前缀，不覆盖旧错误；非对象errors或原设备ok=false也会在顶层报错，回归测试已覆盖

当前为SG90、5V方案，不向模型暴露任意角度servo.set；通过脉宽标定真实机构，避免假设不同批次SG90都精准对应0/90/180度

实际SG90配置必须带当前servo_profile标记，旧大扭矩型号的标定不可直接加载；init先备份旧参数再重置

## 错误传播

本包runtime_source/agent的MCP池检查协议isError和设备JSON里的严格布尔ok

设备失败时直控外层ok也为false，聊天立即返回失败，不再让模型用后续文字掩盖硬件错误；默认不自动重发物理动作

原始upstream_snapshot保留了错误行为，审计结果只描述该固定上游版本，不代表本包运行版仍未修复

## 新版E2E聊天验收

scripts/e2e_test.py及gateway-check使用同一套验收实现。开灯必须有且仅有一次light.set({"on":true})，关灯必须为false；允许穿插无参数devices.status，其他工具、重复按压、非布尔值和多余参数均失败

每条聊天还需对照执行前后devices.status：command_count恰好增加1、requested_on匹配目标、模式与就绪正确、错误为空。通过只证明软件执行一致，lamp_state仍为unknown，不代替现场看灯

新报告的chat_direction_checked及chat_device_state_checked均为true后才可提交现场证据；旧的弱轨迹检查报告不再满足证据门槛

## 验收层次

| 层次 | 命令 | 能证明什么 |
|---|---|---|
| 只读硬件准备 | servo.sh doctor | 实际Pi5平台、引脚复用、周期和访问权限可检查 |
| 空载脉宽 | servo.sh pulse | 需要现场确认真实舵机对PWM的响应 |
| 标定 | servo.sh calibrate | 保存操作员确认的三个实际位置 |
| 本地动作 | servo.sh on/off/cycle | 需要现场确认能真实按开关并退回 |
| MCP检查 | run.sh mcp-check | 协议、schema、状态和动作JSON正确 |
| 网关检查 | run.sh gateway-check | 目标设备的端到端软件链路正常 |
| 现场证据 | run.sh evidence | 记录和视频齐全，不自动认证视频内容 |

SIMULATION_PASS只说明仿真通过，HARDWARE_EVIDENCE_PENDING说明GPIO软件检查后仍需实物证据，BLOCKED表示条件不足，FAIL表示发现错误

报告hardware_verified不由程序自动设为true；操作员证据完整性使用operator_evidence_complete，最终实物验收由现场人员复核
