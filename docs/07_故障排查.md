# 上机故障排查

先明确：doctor不输出PWM，pulse/on/off/cycle需要actuate才会移动；日志和JSON成功均不能代替现场观察

| 现象 | 先查什么 | 如何处理 |
|---|---|---|
| 没有RP1 PWM0 | overlay是否启用、是否已重启 | 检查config.txt中dtoverlay=pwm,pin=12,func=4，查看准备服务状态 |
| pwmchip2不见了 | 控制器编号随内核改变 | 程序自动按98000地址查找，不改成固定0或2，不选9c000风扇控制器 |
| BCM12不是PWM0_CHAN0/a0 | 引脚复用或其他外设冲突 | pinctrl get 12；检查I2S/UART/其他overlay占用，解决后重启 |
| Permission denied | gpio组、准备服务和重新登录 | groups；查看准备服务；加入组后重新登录或重启 |
| 紧急停止锁定 | stop标记仍为1 | 停Agent/MCP，检查机构，再servo reset-stop |
| 文件锁占用/PWM已运行 | 有第二个控制进程 | 先停止已有服务，校准完成后再启动Agent |
| 舵机完全不动 | 红线5V、棕/黑线GND、信号脚号与PWM | 核实红线物理2、棕/黑线物理6、信号物理32；先裸轴测试 |
| 有正确PWM却仍不动 | 实物是否PWM位置型、3.3V输入是否被识别 | 核对型号和卖家输入要求，必要时加非反相电平缓冲，不向GPIO输入5V |
| Pi重启或欠压 | Pi电源余量、SG90负载和线材 | 改独立5V给SG90供电并共地，红线从Pi物理2脚移除，不并联正极 |
| 舵机嗡鸣、机构顶住 | 行程过大、退回不够、SG90扭矩不足 | 先stop，及时切断供电；移开机构后重新小步标定，不能长期堵转 |
| 提示旧型号/配置不匹配 | 是否保留20kg舵机旧配置 | 停止程序后servo init，自动备份旧参数并清除旧标定，再校准SG90 |
| 未标定/非单控 | save是否成功，三个位置是否各不相同 | 重新校准，确认普通单控翘板并实测开关 |
| 超过动作预算 | 窗口过大或步进太慢 | 优先调整机构与缩小工作窗口，满足4.5秒流程预算 |
| Agent在线但没light.set | MCP入口是否仍用原通用设备服务 | 改用本包wall_light_mcp或all_devices_mcp，重启Agent |
| devices.status重名 | 同时启动了两个同名状态工具 | 使用一个合并入口，不依赖后者覆盖前者 |
| 网页只显示通用JSON卡 | 还没有专用light.set按钮 | 使用light.set卡输入on布尔JSON，或先用本包gateway-check |
| 401/403/离线 | 两种令牌、owner归属、设备ID、URL前缀与WS | 向网关负责人核对，不把dev和pat互换 |
| 聊天失败 | 先看直控和MCP | 本地正常后再查模型工具调用与代理，不因聊天失败重复压开关 |

## 常用命令

```bash
bash scripts/servo.sh doctor
systemctl status --no-pager maker-servo-pwm-prepare.service
journalctl -u maker-servo-pwm-prepare.service -n 50 --no-pager
pinctrl get 12
groups
bash scripts/service.sh logs
```

MCP检查的子进程错误日志保存在.runtime/mcp-child.log；分享前检查是否包含私有信息

如果PWM准备服务在第一次未重启前失败，重启后可查看原因并在控制器空闲时执行：

```bash
sudo systemctl restart maker-servo-pwm-prepare.service
```

准备服务发现PWM已使能或控制锁被占用时会拒绝接管，这是为了避免重配运行中的舵机

## 波形应是什么

信号探头接BCM12物理32脚，信号地参考Pi GND/共同负极；预期周期20ms、频率50Hz、高电平约3.3V

1500us脉宽对应7.5%占空比。5V电源脚与3.3V GPIO信号脚用途不同；本项目不需要触碰墙上市电接线

没有示波器时，先确认doctor、空载供电与线序；不能仅凭万用表平均电压断言脉宽正确
