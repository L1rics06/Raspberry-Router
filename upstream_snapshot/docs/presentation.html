01 · 背景与动机

我们要解决什么问题？

🔒

寝室、家里的硬件躲在 NAT 后面——人不在现场，就完全摸不到，更谈不上远程控制。

🧩

🌉
AI 与物理世界缺一座桥

想让 AI 真正「动手」，缺一套低成本、可拆解、能学完整链路的实验平台。

02 · 方案总览

一句话，让千里之外的硬件动起来

🗣 用户说一句话→ ☁️ VPS 中继转发→ 🧠 Agent 理解规划→ 🔧 调用工具 MCP→ ⚡ 硬件真实动作
🗣
自然语言操作物理世界

没有遥控器，语言就是接口；Agent 负责理解与规划，用户只管说。

🔌
MCP 标准化设备接入

每类设备就是一组工具（tool）：加设备 = 加一个工具，即插即用，Agent 代码零改动。

🛰
出站长连接穿透 NAT

树莓派主动向外连接 VPS，校园网、家宽、手机热点都畅通，无需公网 IP。

🧱
四模块契约解耦

接口先行、四线并行开发，本身就是一次完整的工程协作训练。

07 · 模块 B（通信组）

VPS 通信中继 —— 系统的血管

❓
为什么需要 VPS？ 树莓派在校园网 / 家宽的 NAT 后，没有公网 IP、入站不可达。解法：让它主动向外建立 WebSocket 长连接——出站流量在任何网络都畅通，甚至手机热点即可。
🔑
用户鉴权注册登录 · JWT · 用户-设备绑定
📡
设备管理注册 · 心跳 · 在线状态
🔀
双向路由指令下发 · 结果与遥测回传
🧠
LLM 出口代理模型密钥只存 VPS，不落到终端
两步走策略
第 1 步 · 第 1 周 快速通道

frp / SSH 反向隧道先打通「手机 → VPS → 树莓派」，全组尽早看到端到端跑通的希望。

第 2 步 · 正式方案 自研 WebSocket 网关 ✦

Node.js / Go / FastAPI＋JSON 消息协议——教学价值与演示价值最高。

📦 交付 网关服务 · 消息协议文档 · 部署脚本

08 · 模块 C（Agent 组）

树莓派 Agent —— 系统的大脑

设计原则 Agent 保持「薄」：只做三件事——收指令 · 调大模型 · 调工具。设备能力全部由 MCP 工具注入，换硬件不改 Agent。
意图理解用户说了什么→ 工具调用MCP tool→ 观察结果成功 / 失败→ 自然语言汇报回复用户

↺  循环直到任务完成（ReAct 模式）

🧠
LLM 接入

云 API 经 VPS 代理调用（GLM / Qwen / DeepSeek）；ollama 本地小模型作离线彩蛋。

🛡
安全闸门

工具白名单 · 参数强校验 · 高危操作（继电器大电流）二次确认。

⚙️
工程化

systemd 守护进程：开机自启、崩溃自动拉起、断网自动重连。

✍️
关键产出

系统提示词与工具描述文案——直接决定 Agent 好不好用。

💡 技术 Python · mcp 官方 SDK · 手写 tool-use 循环（可选 LangGraph）

10 · 演示设计

可能的演示

候选场景 · 由易到难，最终演示组合视开发进度而定

基础

「千里之外」

可以只用 4G 网络，远程一句话让寝室的风扇转起来、灯亮起来。

★ 证明「真·远程」，穿透 NAT 不是 PPT 概念

基础

「寝室现在多少度？」

可以让 Agent 读取温湿度传感器，用人话回答。

★ AI 长出了「眼睛」，数据变成语言

进阶

「太热了，想办法让我凉快点」

可以让 Agent 自己读温度 → 开风扇 → 汇报决策过程。

★ 这是 Agent 与遥控器的本质区别

彩蛋

「拔网线挑战」

可以现场拔掉树莓派网线再插回：界面离线 → 在线，期间指令不丢。

★ 展示工程可靠性：自愈与消息补发
